EXECUTIVE SUMMARY

1. The Problem & Samsung Motivation

The Mobile Memory Bottleneck

  • 50MP-200MP Camera Sensors: Generate enormous uncompressed 24-bit raw RGB buffers.
  • 120Hz Displays & Real-Time Gaming: Require frames every 8.3ms, choking the LPDDR memory bus and burning battery power.
  • Thermal Throttling: Continuous high memory traffic overheats mobile chipsets, forcing frame rate drops.

Why Simple Approaches Fail

  • Always Lossless (PNG): Safe, but modest compression (2x-3x). Leaves 75% of bandwidth savings unutilized.
  • Always Lossy (JPEG): Big compression (10x-15x), but ruins dark night-mode shots (shadow blocking) and skies (color banding).
  • Fixed Manual Rules ("If dark > 30%"): Only achieved 14.6% savings in practice because manual cutoffs are overly conservative!
OUR SOLUTION: An intelligent pre-compression decision engine that achieves 79.5% memory reduction with zero visible artifacts.
END-TO-END PIPELINE

2. Pre-Compression Decision Architecture

1. Input Buffer

Uncompressed 24-bit RGB frame from Camera ISP or GPU buffer.

2. Dual Space

Convert to ITU-R BT.601 YUV. Decouple Luminance (Y) from Chroma (U/V).

3. 40 Features

Fast O(N) extraction of edges, texture, brightness, noise in < 1ms.

4. ML Decision

Lightweight Decision Tree predicts LOSSY vs. LOSSLESS.

5. Execution

Encode via JPEG (Q=85) or PNG with verified zero quality loss.

Strict Scientific Guarantee: Zero Target Leakage

In hardware, compressed metrics (file size, PSNR, SSIM) DO NOT EXIST before compression happens! Our model inputs strictly contain pre-compression visual statistics. Post-compression metrics are permanently blacklisted and audited via automated unit tests (tests/test_leakage.py).

QUALITY EVALUATION

6. Quality & Artifact Protection Metrics (Step 8)

PSNR (Peak Signal-to-Noise Ratio)

Global pixel-level logarithmic fidelity in decibels (dB). Threshold: >= 33.0 dB. Identical frames return Inf (handled as 100 dB).

SSIM (Structural Similarity Index)

3-channel Gaussian structural correlation (11x11 window). Threshold: >= 0.94 for imperceptible structural degradation on mobile screens.

Dark-SSIM (Shadow Artifact Protection)

Localized SSIM computed strictly over low-luminance pixels (Y < 40). Catches severe DCT blockiness and contouring in shadows on OLED screens.

Banding Risk Score

Quantifies staircase false contouring across smooth gradient regions. Detects artificial step transitions caused by aggressive quantization.

LPIPS Feasibility Study for Mobile Display Pipelines

Learned Perceptual Image Patch Similarity (LPIPS) requires a 50MB-100MB deep neural network (AlexNet/VGG) and 50-120ms GPU inference. While valuable for offline analysis, it is fundamentally incompatible with hard real-time mobile display deadlines (< 2ms). Reserved strictly for offline validation in Milestone 2.

GROUND-TRUTH LABELS

7. Ground-Truth Labeling & Dataset Construction (Step 9)

Multi-Criterion Empirical Decision Rule

An image is labeled LOSSY if and only if ALL four conditions hold; otherwise LOSSLESS:

  • 1. SSIM >= 0.94: High structural fidelity
  • 2. PSNR >= 33.0 dB: Acceptable signal-to-noise ratio
  • 3. Dark-SSIM >= 0.90: Preservation of shadow details (Y < 40)
  • 4. Size Saving >= 25%: Lossy must save at least 25% over lossless

[ASSUMPTIONS REQUIRING MENTOR CONFIRMATION]
All thresholds are fully parameterized in configs/config.yaml for calibration to Samsung internal standards.

Empirical Class Distribution

• LOSSY: 1,018 frames (98.8%)
• LOSSLESS: 12 frames (1.2%)

Why did the 12 frames strictly require LOSSLESS?

  • Flat Posters & UI Icons (edge_04, edge_05): PNG compressed them 4x to 9x smaller than JPEG! Lossy JPEG actually bloated file size (-400% to -900% savings).
  • Smooth Sky Gradients (edge_01): JPEG DCT caused severe false contouring and color banding.
  • Dark Noisy Scenes (edge_02, kodim16-20): Low-light noise caused severe DCT blocking, dropping PSNR < 29 dB and Dark-SSIM < 0.88.

9. Feature Importance & Physical Drivers (Step 10)

What Drives Compressibility Decisions?

  • 1. Dimensions & Area (width, total_pixels): Small UI icons behave radically differently under 8x8 DCT blocks than full-frame camera scenes.
  • 2. Dynamic Range (luminance_range, max_luminance): Extreme contrast governs clipping and shadow quantization noise.
  • 3. Local Spatial Variance (local_variance_mean/std): Measures texture density; high activity masks DCT noise, while flat areas reveal artifacts.
  • 4. Edge Sharpness (std_edge_magnitude): Sharp vector boundaries produce high-frequency ringing under lossy DCT.
  • 5. Chroma Variation (std_b, mean_u): Color saturation dictates required bit budget to prevent color distortion.

  • Depth <= 4 (Only 4 If/Else Checks): Requires zero matrix multiplications or floating-point vector units.
